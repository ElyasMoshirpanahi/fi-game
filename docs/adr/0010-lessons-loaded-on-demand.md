# Books are Sections of Circles of Lessons, loaded on demand from per-book JSON

Decisions 30 to 37 (2026-11-10). A book Section is sized by the book's value (the 20/80 rule applied to the reading list): the ten reading-order must-reads get three Circles, the other must-reads two, the optionals one. A Circle holds three to five Lessons; a Lesson is ten to fifteen Points (Cards) with a Check after every two or three Points and a Fare at the end, about one minute per Point (Parkinson's law made visible). The first Point of every Lesson says what part of the book it distils.

The content no longer fits one file: about 2,600 Cards and 1,000 Checks in two languages. `index.html` keeps a small manifest (every Section, Circle and Lesson with titles and counts); the Lessons' items live in `content/books/v3/bNN.json` on the same origin and are fetched the first time a Lesson of that book opens. ADR-0001 is amended: no external scripts still holds; same-origin data files are allowed. Opening `index.html` from disk shows the Path and plays Basics, but cannot load books.

## Content model

```text
content/books/v3/b01.json          (one per book, 40 to 160 KB)
  { id, title, author, year, stage, must, why, badge, tier,
    circles: [ { id: 'b01c1', title, lessons: [ { id: 'b01c1l1', title, minutes, items: [ ...Points and Checks ] } ] } ] }

index.html, content block
  BOOKS_MANIFEST = the same without items (generated by scripts/build-manifest.mjs)
  sections: basics + one per book, in reading order then stage order; sec.circles = [{ id, title, lessons: [{ id, title, points, checks, minutes }] }]
  stations: s1..s6 plus one stub per Lesson ({ id, book: true, bookId, circleId, name: lesson title, xp: 10, fareSize: 3, items: null })
  content.registerBook(json): fills the stubs' items; content.isLoaded(bookId)
  content.circleOf(lessonId), content.sectionOf(bookId)
```

## Engine and app

- `light()`: a lit Lesson completes its Circle when all the Circle's Lessons are lit (25 XP, event `circle`); a complete Circle completes its Section when all Circles are lit (badge, 50 XP, event `section`). The Library rule stays: the ten reading-order Sections.
- The engine never fetches. The app intercepts `OPEN_STATION` and `OPEN_AT` for a Lesson of an unloaded book: it sets a loading flag, fetches the file, registers it, then dispatches. A saved run inside a Lesson is loaded before HYDRATE. A fetch failure shows a message and leaves the Path as it was.
- Bookmarks snapshot the Card's text when they are made, so the Bookmarks screen never needs a book loaded.
- Migration v2 to v3 (decision 33): keys for the old Units and book Sections are dropped from `lit`, `farePassed`, `rings` and `awarded`; book bookmarks are dropped; a run inside a book is dropped; XP is recomputed as the lit Basics Stations times 50 plus the Milestone. Coins, checklists, journal, habits and shelf stay.

## Consequences

- The Path shows Circles as nodes; tapping a Circle opens its Lesson list with points and minutes.
- The fairness, parity and size rules move to `scripts/validate-book-v3.mjs` and `test/books-v3.test.mjs`, which read the JSON files directly.
- `index.html` drops from 384 KB to roughly 150 KB.
